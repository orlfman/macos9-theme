# A Plasma Control Strip

Make the Control Strip the primary monitor’s system tray. Give it its own short panel at the bottom left, beside the centered Platinum dock. The top bar can then go straight from the global menu and spacer to the clock and Window List. Start by moving the stock System Tray there. If the placement works, build a dedicated tray applet that keeps KDE’s tray machinery and gives it a Control Strip presentation.

## What to take from Mac OS 9

The Mac OS 9.2.2 captures show a 24 px tall strip flush with the bottom-left corner. The expanded example is 483 px wide for the modules installed in that session. Individual module cells are generally about 28–32 px wide, with some variation. The collapsed strip leaves an 18 × 24 px grip. The resting cells use a gray face, a light top and left bevel, and dark dividers. In the sound and sharing captures, the selected cell darkens and its menu opens above it. The volume cell opens a narrow vertical slider with a gray thumb. [Expanded strip and volume slider](../reference/control-strip-volume.png) · [Sound menu](../reference/control-strip-sound-menu.png) · [File sharing menu](../reference/control-strip-file-sharing-menu.png) · [Collapsed strip](../reference/finder-popup-tab.png)

Use that footprint as a starting point. Draw original beveled cells and a textured end grip, and use Platinum’s existing icon theme or new small artwork for Linux controls. Use bottom-left placement and pop-ups that rise from their tiles. The width should follow the current contents. Keep the little grip as a deliberate collapse and reopen control, with a distinct overflow button when there are more items than can fit.

```text
Top menu bar   [Launcher] [Global menu]                         [Clock] [Window List]

Bottom left    [Volume ▸][Network ▸][Bluetooth ▸][App icon][More][Grip]
Bottom center                              [App dock … Trash]

Collapsed      [Grip]
```

## Place the real tray first

In a disposable Plasma session, start with a 24 px horizontal panel on the primary output. Set it to bottom, left-aligned, fit to content, and non-floating. Try **Windows go below** so the strip itself does not reserve more workspace. Plasma 6.8.3 sets no exclusive zone for that mode on Wayland. The Platinum dock already occupies the same edge, so the important placement check is what happens as the dock or tray grows, especially on narrower or scaled outputs. [Plasma panel scripting API](https://develop.kde.org/docs/plasma/scripting/api/#panels) · [Plasma 6.8.3 panel reservation code](https://github.com/KDE/plasma-workspace/blob/v6.8.3/shell/panelview.cpp#L1441-L1458)

Use the panel scripting API’s `addWidget(existingWidget)` to move the configured tray. Plasma 6.8.3 transfers the existing applet object between containments through that overload. Check tray preferences and child applet settings after reload and restart. A fresh layout can create the tray in the strip panel directly. The current theme adds the tray to the top bar in both its sandbox layout script and its look-and-feel layout. Any eventual integration should account for both entry points, while migration of an existing layout can target the tray and its destination directly. [Plasma 6.8.3 widget transfer](https://github.com/KDE/plasma-workspace/blob/v6.8.3/shell/scripting/containment.cpp#L200-L215) · [Theme sandbox layout](../plasma/layout.js#L35) · [Theme look-and-feel layout](../plasma/look-and-feel/platinum.desktop/contents/layouts/org.kde.plasma.desktop-layout.js#L36)

## Build the strip as a tray applet

Plasma 6.8.3’s System Tray is a compiled applet with a custom embedded containment. It merges three types of entries into its model. KDE applets such as volume and network have their own compact and expanded views. Third-party tray icons arrive as StatusNotifierItems over D-Bus. Plasma also supplies background-app entries. The tray already handles discovery and lifecycle, item visibility, input dispatch, and Wayland menu anchoring. A StatusNotifier-only applet would cover third-party icons while leaving the KDE controls and background-app list to separate integrations. [Plasma 6.8.3 tray implementation](https://github.com/KDE/plasma-workspace/blob/v6.8.3/applets/systemtray/systemtray.cpp#L366-L394) · [Status Notifier Item specification](https://specifications.freedesktop.org/status-notifier-item/latest-single/)

For per-item bevels and a grip that collapses the entire tray, prototype a small fork of the 6.8.3 tray under its own plugin ID. Keep KDE’s model, applet registry, StatusNotifier host, settings, and delegates. Put the first changes in the compact QML layout and draw the cells underneath the existing controls so they keep their pointer and keyboard handling. Keep the stock hidden-items view and full applet pop-ups working first. The stock tray QML is registered by the compiled plugin’s build, and its views call into the tray’s own C++ object. Treat reuse of the installed private QML module across plugin boundaries as an experiment, with the matching upstream source as the build baseline. [Tray applet build](https://github.com/KDE/plasma-workspace/blob/v6.8.3/applets/systemtray/CMakeLists.txt) · [Tray QML](https://github.com/KDE/plasma-workspace/blob/v6.8.3/applets/systemtray/qml/main.qml) · [KDE applet input handling](https://github.com/KDE/plasma-workspace/blob/v6.8.3/applets/systemtray/qml/PlasmoidItem.qml)

The stock panel chooses the same south-edge frame for both bottom panels. Use it for the placement prototype and see how much the tray’s own frame can cover. The installed panel view honors `NoBackground` on the panel containment itself. If the stock frame still shows around the strip or prevents the collapsed grip from fitting, a dedicated panel containment is an option to test. This keeps any background change local to the strip and lets the dock keep its existing frame. [Installed panel view](/usr/share/plasma/shells/org.kde.plasma.desktop/contents/views/Panel.qml#L149) · [Theme panel findings](../docs/FINDINGS.md)

## Drag the strip along the screen edge

For the movable version, start at the bottom left and let the user drag the grip up or down. The strip stays horizontal, with its left edge flush to the display, even when collapsed. A click still toggles collapse. Start the move after the pointer passes a drag threshold, and remember the height on release. Reopen at that same height and clamp the position below the menu bar and above the bottom of the display.

The stock bottom panel is a fixed-position prototype for this interaction. On Wayland, Plasma 6.8.3 applies its panel offset along the panel’s own axis. A horizontal panel can slide left and right along the bottom. A panel attached to the left edge can slide vertically, and Plasma gives it a vertical layout. [Plasma 6.8.3 panel positioning](https://github.com/KDE/plasma-workspace/blob/v6.8.3/shell/panelview.cpp#L540-L625)

A movable horizontal strip can use its own Wayland layer-shell surface with left and top anchors, a zero left margin, and a top margin that follows the drag. Change the surface width when the strip collapses and use a non-reserving exclusive zone. Prototype the surface with the grip, one live KDE tray control, and one StatusNotifierItem. Check dragging and pop-up placement in both states, including after a scale or output change. The integration question is whether the custom surface can host KDE’s tray views and menus with their existing Plasma context. [KDE LayerShellQt API](https://github.com/KDE/layer-shell-qt/blob/v6.8.3/src/interfaces/window.h) · [Wayland layer-shell anchors and margins](https://wayland.app/protocols/wlr-layer-shell-unstable-v1#zwlr_layer_surface_v1:request:set_margin)

## Interaction and defaults

- **Show the controls users reach for.** Start with volume and network. Let Bluetooth, battery and brightness, clipboard, notifications, and other modules follow the stock tray’s availability and visibility settings. Third-party entries keep their own icons, activation, middle-click, context-menu, wheel, and attention behavior where provided.
- **Collapse the view and keep the tray running.** Leave the same model and child applets alive, close the active pop-up, and shrink the panel to its grip. Save the open or closed state. Give the grip a focus indicator and accessible name, and show an attention cue there when a hidden item requests attention. Move keyboard focus back to the grip when collapsing.
- **Budget space before laying out tiles.** Keep the visible entries in one row and reserve space for the grip and overflow button. Send the entries that exceed the width budget to the same pop-up as items the user has chosen to hide. Keep the currently open tile anchored while its pop-up is up. Test a width cap against the dock’s largest expected footprint before adding any logic to track a neighboring panel.
- **Make volume the first custom pop-up.** Once the stock volume view works in the strip, try a narrow, upward-opening master-volume slider that follows the system’s volume and mute state. Keep easy access to KDE’s full mixer for device and per-app controls. Leave the other controls on their stock pop-ups initially.

## Prototype checks

1. **Placement and rollback.** In nested KWin with its own session bus and XDG directories, move the stock tray, restart the shell, and move it back. Check that its icon policy and child settings survive, that the top bar has one fewer widget, and that both bottom panels remain independently usable. Check primary-output changes and a narrower output at 100% and 150% scale. Use a sandbox owned by this project. [Theme’s nested Plasma harness](../dev/plasma-test.sh)
2. **Replacement compatibility.** Load the new plugin ID in the disposable session and switch to it as the sole visible tray. Test KDE child applets, normal and menu-only StatusNotifierItems, overflow, attention, and app exits and restarts. Verify that notification history and prompts still work during and after the switch. KDE’s panel-copy code gives the stock tray ID special handling, so exercise config import and rollback explicitly before offering an in-place replacement. Record the Plasma version used to build the plugin and recheck it after upgrades. [Plasma 6.8.3 tray configuration copy](https://github.com/KDE/plasma-workspace/blob/v6.8.3/shell/shellcorona.cpp#L2449-L2496)
3. **Appearance and focus.** Capture the expanded strip, grip-only state, pressed tile, overflow, and vertical volume slider. Verify that pop-ups open upward on the correct output, stay on-screen, close with Escape, and return focus. Use the reference images locally for comparison. Keep original Apple artwork out of the package and retain upstream license notices for any KDE files the applet incorporates.
